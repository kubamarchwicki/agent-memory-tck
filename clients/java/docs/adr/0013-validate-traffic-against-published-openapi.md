# Validate client traffic against the published OpenAPI contract

Java client HTTP behavior is verified against `clients/java/docs/openapi.json`, a byte-identical vendored copy of the Swagger 2.0 document the hosted service publishes at `https://memory.neo4jlabs.com/openapi.json`. Validation uses `com.atlassian.oai:swagger-request-validator-wiremock-junit5:2.46.1` (the successor `openapi-request-validator-wiremock-junit5:3.0.0` artifact is Java-21-only bytecode and this project targets Java 17, so the older, Java-8-targeted artifact family is vendored instead) as a test-scope dependency, but only for its `OpenApiInteractionValidator` class, not as a registered WireMock extension: `OpenApiContract` builds one `OpenApiInteractionValidator` directly and its `assertEveryExchangeMatchesTheContract()` method calls `.validate(request, response)` synchronously and directly on every recorded exchange from `@AfterEach`, converting each WireMock `LoggedRequest`/`LoggedResponse` via `WireMockRequestResponseUtil`. This validates both halves of every WireMock interaction — path, method, parameters, request body, the declared `Authorization` security header, content types, and response status — and a small local rule additionally rejects any outbound body property the operation's request definition does not declare. That second rule is deliberately stricter than the document: no definition sets `additionalProperties: false`, so a misspelled property name would otherwise validate cleanly forever. Each of the thirteen mapped operations owns its stub and its test rather than sharing a parameterized table or a catch-all responder, so one operation's contract can be read in one place. An earlier version of this design registered the library's `OpenApiValidator` as a global WireMock `PostServeAction` extension instead; that was abandoned because `PostServeAction`s dispatch asynchronously, on a background thread, after the response has already returned to the client, which is incompatible with an immediate `@AfterEach` check and meant validation silently gated nothing.

Response bodies are synthesized from each operation's declared 2xx schema and populated for every documented property, rather than hand-written or recorded from the hosted service. The document declares no `format` on any of its 578 properties and no enum on any response property, so four conventions live inline in the test code: id-shaped properties are UUIDs, `createdAt` and `updatedAt` are ISO-8601 instants, and `role` and `status` take the values this client binds. Those conventions are the record of where the client relies on observed hosted behavior rather than on the contract — `Message.id` is a `UUID` and `ToolCall.createdAt` is an `Instant` because the service behaves that way, not because the document says so. A companion overlay file carrying the same constraints was considered and rejected as machinery: the conventions are few, they belong beside the code that needs them, and the vendored document stays exactly what the service publishes. Where a mapping is not obvious, the synthesized value is the plain string the document declares.

The consequence is a suite that proves conformance, not correctness. It cannot see the prose-only constraints the schema omits — notably that `Conversation.messages()` sends no `limit` and is therefore capped at the service default of 50 — and its response validation is close to tautological, because fixtures are generated from the schema they are then checked against. The real response-side value is that the client decodes a fully populated documented shape without throwing. Value-level assertions stay in the existing focused tests, and `MemoryClientHttpTransportTest` is retained unchanged: the ADR 0012 omission guarantee is not expressible in this contract, since an omitted optional property and a present one are equally legal.

Because a vendored snapshot can age without any test failing, a Failsafe check fetches the published document and fails when it differs from the vendored copy, skipping when the network is unavailable. The document is served unauthenticated, so this check needs no credentials and stays independent of the credential-gated `HostedServiceIT`.
